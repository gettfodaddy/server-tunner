# Node Tuning

Интерактивный инструмент для Linux-сервера с оформлением в стиле установщика Selfsteal, без логотипа. Требуются root, Python 3.9+, systemd, `ip`, `tc`, `sysctl`, `findmnt` и стандартные утилиты Linux. Изменения применяйте сначала на отдельной тестовой ноде.

## Что делает

1. **Проверка** показывает компактную сводку сети, очереди внешнего интерфейса, памяти, swap, conntrack, диска, нагрузки и Docker. Чтобы увидеть полный вывод команд, после сводки выберите `д`. Проверка не загружает модули, не скачивает данные и не меняет настройки. Данные Docker и conntrack отображаются, если доступны.
2. **BBR** предлагает включить уже доступный алгоритм TCP. Создаёт `/etc/sysctl.d/90-prism-node-tuning.conf` и сохраняет прежнее текущее значение. Модуль автоматически не загружается. Значения для TCP-буферов, таймаутов и очередей не изменяются.
3. **Swap** анализирует RAM, текущий swap, свободное место и файловую систему, предлагает размер и позволяет выбрать его вручную. Создаёт отдельный файл только при отсутствии активного swap, не перезаписывает существующий файл и не трогает чужие swap-разделы. Поддерживаются только ext4 и XFS; файл заполняется нулями. При отключении для отката проверяется доступная память. Значение swappiness не меняется.
4. **CAKE** настраивает исходящую очередь на интерфейсе с единственным маршрутом по умолчанию. Скорость выбирает пользователь по результатам измерений. Смена временная: после перезагрузки CAKE не устанавливается снова. Автоматический режим разрешён только для одной очереди `fq` или `fq_codel` с распознаваемыми параметрами; многоканальные и сложные конфигурации намеренно отклоняются. На приёмном направлении отдельная очередь не создаётся.
5. **Откат** показывает активные изменения и откатывает выбранное. Записи о BBR, swap и CAKE независимы, поэтому эти режимы можно использовать одновременно. При ошибке запись сохраняется для повторной попытки. При внешнем изменении управляемого файла, swap или очереди откат останавливается для ручной проверки.

Инструмент не изменяет firewall, не перезапускает Docker и не пересоздаёт контейнеры, не удаляет логи, не изменяет системные лимиты и не меняет чужой swap. Никакой прирост скорости не гарантирован: измеряйте соединение со стороны пользователей до и после изменения.

## Перенос на сервер из Windows

В PowerShell на компьютере замените `root` и `SERVER_IP` на свои значения:

```powershell
scp -r "C:\Users\Ivan\Documents\Codex\2026-10-06\new-chat\node-tuning" root@SERVER_IP:/opt/
```

Подключитесь к серверу:

```powershell
ssh root@SERVER_IP
```

Запустите инструмент:

```bash
cd /opt/node-tuning
sudo bash install.sh
```

Начните с пункта **1 — Проверить сервер**. Затем выбирайте отдельные действия. Перемещение файлов или удаление каталога программы не отменяет изменения на сервере.

Интерфейс очищает экран перед меню и показывает короткие анимации. Результаты и ошибки остаются на экране до нажатия Enter. Для работы без анимации или очистки доступны:

```bash
sudo env NO_ANIMATION=1 NO_CLEAR=1 bash install.sh
```

Для отключения цветов добавьте `NO_COLOR=1`.

## Обновление через GitHub

На рабочем ПК в PowerShell:

```powershell
cd 'C:\Users\Ivan\Documents\Codex\2026-10-06\new-chat\node-tuning'
git status
git add node_tuning.py README.md
git commit -m "Fix CAKE queue parsing and improve terminal UI"
git push origin main
```

На сервере, если проект уже клонирован в `/opt/node-tuning` и там нет локальных изменений:

```bash
cd /opt/node-tuning
git status
git pull --ff-only origin main
sudo bash install.sh
```

Если серверная папка содержит локальные изменения, сначала сохраните их и разберите вывод `git status`; не выполняйте принудительный сброс. Если проект не клонирован через Git, склонируйте его в отдельный новый каталог, не перезаписывая старый. Состояние ранее выполненных настроек хранится отдельно от кода в `/var/lib/prism-node-tuning`.

## CAKE: выбор скорости и откат

Измерьте реальную устойчивую исходящую скорость ноды в нескольких запусках. Подберите немного меньший лимит и сравните задержку под нагрузкой, скорость и CPU. Общего безопасного числа для всех VPS нет. Ограничение применяется ко всем исходящим подключениям интерфейса и может замедлить пользователей. Скрипт не предполагает, что узкое место находится на сервере, и не обещает исправление bufferbloat у провайдера или клиента.

Снимок хранит исходный тип и распознанные параметры очереди, но после перезагрузки автоматически восстановить прежнюю очередь невозможно: сетевые службы могут настроить её иначе. Пункт отката в этом случае сообщит о перезагрузке и оставит действующую очередь без изменений. Для постоянного CAKE требуется отдельная настройка, зависящая от системы управления сетью.

## Восстановление

В меню выберите **5 — Откатить последнее изменение**, затем нужный пункт. Файлы состояния и снимки конкретных изменений: `/var/lib/prism-node-tuning/current.json`. Если операция прервана, её состояние будет показано как `prepared`; попробуйте откат. При ошибке сохраните сообщение и проверьте состояние вручную до повторного запуска.

Для swap скрипт удаляет только свою запись в `/etc/fstab` и только созданный им файл. Если при установке запись или файл изменились извне, потребуется ручная проверка. Если оперативной памяти недостаточно для `swapoff`, сначала освободите память и повторите откат.

Sysctl BBR применяется сейчас и прописывается для последующих загрузок. Другие файлы sysctl могут иметь более высокий приоритет; после перезагрузки проверьте `sysctl net.ipv4.tcp_congestion_control`. Изменение воздействует на новые TCP-соединения, а не гарантированно на уже открытые.
